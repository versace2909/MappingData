### Requirement: BaseEntity uses int for Id with auto-increment
`BaseEntity` SHALL declare `Id` as `int` with `protected set`. EF Core SHALL configure it as an identity/auto-increment column (database-generated on add).

#### Scenario: Entity Id is int type
- **WHEN** a domain entity class inherits `BaseEntity`
- **THEN** its `Id` property is of type `int` and is generated by the database on insert

---

### Requirement: BaseEntity centralizes audit fields
`BaseEntity` SHALL define `CreatedDate`, `UpdatedDate`, `CreatedBy`, and `UpdatedBy` as the single source of these audit fields for all domain entities. No entity class SHALL redeclare these properties.

#### Scenario: Entity inherits audit fields
- **WHEN** `DataSource` or `DataSourceDetail` is instantiated
- **THEN** `CreatedDate`, `UpdatedDate`, `CreatedBy`, and `UpdatedBy` are accessible via inheritance from `BaseEntity`

---

### Requirement: Audit fields set via BaseEntity methods
Command handlers and application services SHALL use `BaseEntity.SetCreatedBy()` to assign the creator, rather than directly setting `CreatedBy` via object initializer.

#### Scenario: Upload sets CreatedBy via method
- **WHEN** `UploadDataSourceCommandHandler` creates a `DataSource`
- **THEN** `SetCreatedBy("Admin")` is called on the entity (not `CreatedBy = "Admin"` in initializer)

---

### Requirement: DataSource inherits BaseEntity
`DataSource` SHALL inherit from `BaseEntity` and SHALL NOT redeclare `Id`, `CreatedBy`, `UpdatedBy`, `CreatedDate`, or `UpdatedDate`.

#### Scenario: DataSource entity compiles without duplicate audit fields
- **WHEN** the project is compiled
- **THEN** `DataSource` has no direct declarations for `Id`, `CreatedBy`, `UpdatedBy`, `CreatedDate`, or `UpdatedDate`

---

### Requirement: DataSourceDetail inherits BaseEntity
`DataSourceDetail` SHALL inherit from `BaseEntity` and SHALL NOT redeclare `Id`, `CreatedBy`, `UpdatedBy`, `CreatedDate`, or `UpdatedDate`.

#### Scenario: DataSourceDetail entity compiles without duplicate audit fields
- **WHEN** the project is compiled
- **THEN** `DataSourceDetail` has no direct declarations for `Id`, `CreatedBy`, `UpdatedBy`, `CreatedDate`, or `UpdatedDate`

### Requirement: EF migration reflects clean model
After the refactor, a new EF Core migration SHALL be generated that produces the same `data_source` and `data_source_detail` table schema as the prior migration.

#### Scenario: New migration generates correct schema
- **WHEN** `dotnet ef migrations add` is run after the code changes
- **THEN** the generated migration creates `data_source` and `data_source_detail` tables with columns `id` (uuid), `created_by`, `updated_by`, `created_date`, `updated_date` and all entity-specific columns
